# Stability audit — 2026-09-10

本轮稳定性检查最初在工作区完成；用户随后授权发布，本次修复纳入 0.9.4（构建号 30）。以下验证范围保持不变，不将发布或离线测试通过等同于真实字幕补翻成功。

## 已确认的根因

0.9.3 在单条补翻时将完整原文放入 JSON Schema 的 `source.enum`。用户截图中的服务错误明确指出：严格结构化输出不接受这里包含换行的字符串字面值，返回 `invalid_json_schema`。这是应用构造请求的回归，不是用户字幕文件错误，也不是缺少登录。

修复：Schema 只约束结构、字段类型和可用 ID；字幕原文留在提示词中。原文对应关系、ID 完整性、非空正文、标签和换行仍由本地校验器严格检查，没有通过放宽错位检查来隐藏错误。

参考官方说明：[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)、[Codex non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)。具体的换行限制以此次真实服务报错为依据，不将离线 Schema 测试视为服务兼容性证明。

## 本轮检查和修复

| 路径 | 修复 |
| --- | --- |
| 请求与错误处理 | 解开嵌套 JSON 错误，只显示有限长度、脱敏后的错误摘要；无效 Schema/请求不会自动反复补翻。额度错误不再被含有 `model access` 的措辞误判成模型下线。 |
| 界面状态 | 出错时不再同时显示绿色“已准备好开始”；无效请求不提供无效的重复翻译入口。 |
| 流式结果与恢复 | 已校验并保存的流式条目不再被最终汇总重复保存或改写；恢复的正文重新检查格式，坏的保存项进入补翻而非直接导出。 |
| 输出安全 | 提前检查输出路径、覆盖权限、同文件的符号链接/硬链接；写入前再检查输出和视频文件身份，避免长时间处理后输出位置变化或视频被替换。 |
| 完成状态 | 成品已写入后，清理进度缓存失败不再被报告成整次翻译失败。 |
| 取消 | 文件夹遍历和 Whisper 模型校验的 detached task 接收外层取消；避免取消 UI 后继续扫描目录/读取大型模型。 |
| 子进程退出 | 父进程退出后非阻塞、有上限地排空管道，避免继承 stdout 的后代进程使 `readToEnd()` 无期限等待。 |

同时复查了字幕写入与时间轴校验、进度保存、失败条目补翻边界、提取缓存、分批任务及 OCR 的取消路径。未为追求速度加入无界并发、无限重试或静默切换模型。

## 剩余验证与限制

1. Hoppers 的第 99、106 条及单独第 99 条真实补翻仍需用户另行授权后实测；本次应用户要求发布，保留此未验证项，不能以 Mock 通过宣称真实服务补翻已经成功。
2. 更早的第 99/106 条对齐失败没有保留原始失败模型结果，因此不能确定当时是原文回显、标签还是换行不符。此次能确认的是截图中的请求 Schema 回归。
3. 大模型仍可能返回缺失或无效条目。保留有上限的补翻与本地校验，失败时保留通过的条目，不输出伪成功或空字幕。
4. 字幕提取缓存目前是有大小限制的内存缓存；退出/更新应用后首次恢复仍可能需要重新提取，已保存译文不因此丢失。
5. 未进行整部影片的 OCR/Whisper 性能基准或 iOS 真机回归；不能承诺所有路径已无 Bug。
